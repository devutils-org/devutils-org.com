01 / SAYS WHAT IT CANNOT SEE

“Out of reach” is an answer too.

Before measuring, omn checks what this machine can actually serve — and counts what it can’t, instead of leaving it out.

$ omn list | tail -n 3 | head -n 1
101 sources: 92 usable here, 0 unverified,
9 out of reach on this machine.

02 / REFUSES RATHER THAN GUESSES

No answer to a different question.

When a program declares no request boundary, omn won’t make one up from the connection: it refuses, and says how to get the real thing.

net.request was not served:
/usr/bin/sh declares no request […]
Nothing is inferred from the connection
instead -- see docs/scenarios/vertical.md

03 / LOOKS BEFORE IT TOUCHES

Read first. Act on a plan.

pkgx doesn’t install or remove straight away: it writes a plan you can read, save and dry-run, and only that plan is ever applied.

$ pkgx plan apt:curl --save preview.json --expires-in 300
$ pkgx apply --plan preview.json --dry-run
PKGX
04 / TIES A FAILURE TO ITS CAUSE

Not just “it broke on Rocky 8”.

distroproof runs your program on the real kernel of each distro, then compares the environments — so a failure arrives with the difference that explains it.

$ distroproof run --target rocky-8 -- envprobe --json > rocky8.json
$ envprobe diff local.json rocky8.json   # exit 1 if they differ
