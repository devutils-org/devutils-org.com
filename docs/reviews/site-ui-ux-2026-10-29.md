# Site UI/UX audit — 29 October 2026

The Library keeps the site's existing art direction: Inter, the near-black background, cyan/violet accents, gradient headings, glass panels, shared corner radii and light pill buttons. Its entry points are reorganized around search, three starting paths, an expandable subject index and history/figures/labs. Counts and course links come from the published content. Untranslated entries and the English search default are explicit.

## Scope and evidence

The production build contains 484 HTML documents: 24 main/tool pages, 233 Library documents, 153 book documents and 74 redirect documents. The full browser sweep made 968 visits at 1440px and 375px. Redirect destinations were checked; automated WCAG A/AA checks ran on the non-redirect documents. The sweep checks HTTP responses, main landmarks, one primary heading, horizontal overflow, runtime exceptions and automated accessibility findings. It does not constitute a manual WCAG certification or user research.

The initial sweep found 148 page/viewport occurrences of one issue class: non-focusable scrollable regions. The second sweep found zero accessibility or layout issues. Additionally, all 217 published article documents were checked on mobile with their native details panels expanded: no horizontal overflow or automated accessibility findings.

Representative screenshots were inspected for the home page, Tools, About and Library in desktop/mobile layouts. Existing designs and navigation conventions were retained.

## Corrections

- Library surfaces and controls use the shared glass treatment, colors and radii instead of a separate opaque violet palette.
- Article contents on mobile are a native disclosure below the title. They remain available without JavaScript; the desktop contents rail is retained.
- Installation commands, terminal regions and Omniscient's session examples can receive keyboard focus for scrolling.
- All book code blocks become focusable during the build. The site's book stylesheet supplies their cyan focus outline. These adaptations also work without JavaScript and survive a fresh upstream book export followed by the site build.
- Book arrow-key scrolling inside code does not trigger previous/next-page shortcuts. Closed book sidebars are inert, Escape closes the mobile sidebar, and dismissing search restores focus to its button.
- Mobile auto-selection and incidental pointer hover on tool workflow cards no longer override keyboard-focused cards.

- `bench/contributions.ts`: eight desktop/mobile pages, downloads and bilingual navigation.
- `bench/section-navigation.ts`: 16 layouts, centered content, desktop rail and mobile contents.
- `bench/history.ts`: 44 page layout/accessibility checks plus chapter navigation, timeline filters, aliases and ten search targets.
- Library hub: eight EN/FR viewport checks at 375, 768, 1024 and 1440px; 61 course links; keyboard disclosures; actual search submissions; automated accessibility.
- Additional interaction scenarios: 23 passes covering terminal tabs, workflow cards, command copying, book search/sidebar/code scrolling, mobile article contents and no-JavaScript keyboard access.

The full generated-site sweep is reproducible after starting `npm run preview -- --host 127.0.0.1 --port 5178`:

```sh
CHROME_PATH=/path/to/chrome node bench/site-ux.mjs
```

`CHECK_BASE_URL` and `CHECK_OUTPUT` override the server and artifact directory. The command writes per-document results, findings and screenshots and exits unsuccessfully when findings remain. Session artifacts are in `/private/tmp/devutils-site-ux-audit/`; additional checks and captures are in the respective `/tmp/devutils-*-check/` directories and `/private/tmp/library-ux-*` files. Browser evidence is from headless Chrome with reduced motion; other browser engines were not exercised.

## Qualitative follow-up beyond Library

Hero buttons explored during the follow-up were removed after visual review with the site owner: the opening sections preserve space for the existing animation. The shared hero renderer and both home languages retain their original action-free composition.

- Contributions: Projects navigation leads to the actual project records rather than the preceding explanation. Evidence, metrics and dated upstream statuses are retained.
- The 320px follow-up exposed overflowing ATFQ layer examples; their code regions now support keyboard scrolling.

Before the hero-button removal, the follow-up covered 24 main/tool pages in EN/FR at 1440, 375 and 320px, with 72 passing anchor, responsive and automated accessibility checks. Home and Contributions also passed their existing no-JavaScript and bilingual browser checks. These checks are not user research.
